ENDPOINTS DE LA API — SKILLMATCH
Proyecto: SkillMatch
Base URL: http://localhost:3000
Tecnologías: Node.js, Express, MySQL/MariaDB, bcrypt y JWT

Rutas protegidas: requieren el encabezado "Authorization: Bearer <token>".
Las escrituras del catálogo (categorías y habilidades) requieren rol administrador.
Las habilidades del usuario (sección 5) requieren un usuario autenticado y operan
solo sobre sus propios registros.
Las solicitudes de conexión y las conexiones (secciones 6 y 7) también requieren
un usuario autenticado y solo permiten actuar sobre los registros propios.
La mensajería (sección 8) solo permite leer y escribir en las conexiones en las
que el usuario participa y solo envía mientras la conexión esté activa.
Las calificaciones (sección 9) solo se crean sobre conexiones finalizadas en las
que el usuario participó, una sola vez por participante y por conexión.

2. HABILIDADES

GET /api/habilidades
Descripción: Lista las habilidades con filtros opcionales y paginación.
Parámetros de consulta (todos opcionales):
  categoriaId -> entero positivo. Solo habilidades de esa categoría.
  nombre      -> texto de hasta 100 caracteres. Coincidencia parcial.
  estado      -> activo | inactivo
  orden       -> nombre (A-Z, por defecto) | recientes (últimas creadas)
  page        -> entero entre 1 y 100000 (por defecto 1)
  limit       -> entero entre 1 y 50 (por defecto 10)
Respuesta exitosa: 200 OK
{
  "success": true,
  "message": "Habilidades consultadas correctamente.",
  "data": [ ... ],
  "paginacion": {
    "pagina": 1,
    "limite": 10,
    "total": 8,
    "totalPaginas": 1,
    "tieneAnterior": false,
    "tieneSiguiente": false
  }
}
Nota: si un parámetro no es válido, responde 400 con la lista de errores.

GET /api/habilidades/:id
Descripción: Consulta una habilidad por su identificador.
Respuesta exitosa: 200 OK

  "estado": "activo"

Respuesta exitosa: 201 Created

PUT /api/habilidades/:id

Encabezado:
Authorization: Bearer <token>

  "descripcion": "Lenguaje de programación para desarrollo web",

DELETE /api/habilidades/:id

Authorization: Bearer <token>
Respuesta exitosa: 200 OK

=========================================================
3. AUTENTICACIÓN
=========================================================

POST /api/auth/registro
Descripción: Registra un nuevo usuario.
Cuerpo:
{
  "nombres": "Diego",
  "apellidos": "Santander",
  "correoElectronico": "diego@example.com",
  "contrasena": "12345678",
  "alias": "diegosantander"
}
Respuesta exitosa: 201 Created
El rol asignado se obtiene por nombre desde la tabla rol (siempre "usuario").
La respuesta incluye los campos idRol y rol.

POST /api/auth/login
Descripción: Inicia sesión y devuelve un token JWT.
Cuerpo:
{
  "correoElectronico": "diego@example.com",
  "contrasena": "12345678"
}
Respuesta exitosa: 200 OK
El token incluye idUsuario, idRol, rol y correoElectronico.
También se actualiza la fecha de último acceso del usuario.

Roles del sistema:
  id_rol = 1 -> usuario
  id_rol = 2 -> administrador (se asigna manualmente con UPDATE usuario)


=========================================================
4. USUARIOS
=========================================================

GET /api/usuarios/perfil
Descripción: Consulta el perfil del usuario autenticado.
Protegido: Sí
Encabezado:
Authorization: Bearer <token>
Respuesta exitosa: 200 OK
Nota: incluye "calificacion" con el promedio y el total de calificaciones
recibidas (sección 9).

PUT /api/usuarios/perfil
Descripción: Actualiza el perfil del usuario autenticado.
Protegido: Sí
Encabezado:
Authorization: Bearer <token>
Cuerpo:
{
  "nombres": "Diego Alejandro",
  "apellidos": "Santander Toro",
  "alias": "diegosantander",
  "biografia": "Estudiante de ingeniería de sistemas",
  "fotoPerfilUrl": "https://ejemplo.com/foto.png",
  "disponibilidad": "Tardes y fines de semana",
  "ciudad": "Bogotá",
  "pais": "Colombia"
}
Nota: "nombres" y "apellidos" son obligatorios. Los cinco campos finales son
opcionales y se guardan en la tabla perfil; si no se envían, se conserva el
valor anterior. Enviar null o una cadena vacía limpia el campo.
Respuesta exitosa: 200 OK

GET /api/usuarios
Descripción: Busca usuarios activos por nombre, ubicación o habilidades.
Protegido: No
Parámetros de consulta (todos opcionales):
  nombre             -> busca en nombres, apellidos y alias (hasta 100 caracteres)
  ciudad             -> ciudad del perfil (hasta 80 caracteres)
  pais               -> país del perfil (hasta 80 caracteres)
  habilidadOfrecida  -> usuarios que ofrecen una habilidad con ese nombre
  habilidadRequerida -> usuarios que desean aprender una habilidad con ese nombre
  page               -> entero entre 1 y 100000 (por defecto 1)
  limit              -> entero entre 1 y 50 (por defecto 10)
Respuesta exitosa: 200 OK
{
  "success": true,
  "message": "Usuarios consultados correctamente.",
  "data": [
    {
      "idUsuario": 3,
      "idRol": 1,
      "rol": "usuario",
      "nombres": "Ana",
      "apellidos": "Gómez",
      "alias": "anagomez",
      "fechaRegistro": "2026-11-12T17:05:39.000Z",
      "perfil": { ... },
      "habilidades": {
        "ofrecidas": [ ... ],
        "requeridas": [ ... ]
      }
    }
  ],
  "paginacion": { "pagina": 1, "limite": 10, "total": 1, "totalPaginas": 1 }
}
Nota: solo se listan cuentas con estado "activo" y nunca se devuelve el correo
electrónico ni la fecha del último acceso. Los textos usan coincidencia parcial.
Si un parámetro no es válido, responde 400 con la lista de errores.

GET /api/usuarios/:id
Descripción: Consulta la información pública de un usuario, incluidos sus
registros en "habilidades.ofrecidas" y "habilidades.requeridas".
Protegido: No
Respuesta exitosa: 200 OK
Nota: incluye "calificacion" con { promedio, total } de las calificaciones
recibidas (sección 9).

5. HABILIDADES DEL USUARIO

Todas las rutas son privadas: el usuario se identifica con el token y solo puede
consultar o modificar sus propios registros.
Valores permitidos:
  nivel / nivelDeseado -> basico, intermedio, avanzado
  estado               -> activo, inactivo

GET /api/habilidades-usuario/ofrecidas
Descripción: Lista las habilidades que ofrece el usuario autenticado.
Protegido: Sí
Encabezado:
Authorization: Bearer <token>
Respuesta exitosa: 200 OK

POST /api/habilidades-usuario/ofrecidas

Protegido: Sí
Encabezado:

  "nivel": "avanzado",

{

Nota: todos los campos son opcionales, pero se debe enviar al menos uno (400).

Respuesta exitosa: 200 OK

DELETE /api/habilidades-usuario/ofrecidas/:id

=========================================================
6. SOLICITUDES DE CONEXIÓN
=========================================================
Todas las rutas son privadas: el usuario se identifica con el token y solo puede
consultar o responder las solicitudes en las que participa.
Valores permitidos:
  estado -> pendiente, aceptada, rechazada, cancelada
  page   -> entero entre 1 y 100000 (por defecto 1)
  limit  -> entero entre 1 y 50 (por defecto 10)

POST /api/solicitudes
Descripción: Envía una solicitud de conexión a otro usuario.
Protegido: Sí
Encabezado:
Authorization: Bearer <token>
Cuerpo:
{
  "idUsuarioReceptor": 8,
  "mensajeInicial": "Hola, vi que ofreces JavaScript y yo puedo ayudarte con diseño."
}
Nota: "mensajeInicial" es opcional (máximo 500 caracteres). No se puede enviar
una solicitud a uno mismo (400). El receptor debe existir (404) y estar activo
(409). No puede haber otra solicitud pendiente entre ambos, sin importar quién
la envió (409), ni una conexión activa entre los dos (409).
Respuesta exitosa: 201 Created

GET /api/solicitudes/recibidas
Descripción: Lista las solicitudes que otras personas enviaron al usuario.
Protegido: Sí
Encabezado:
Authorization: Bearer <token>
Parámetros opcionales: estado, page, limit
Ejemplo: GET /api/solicitudes/recibidas?estado=pendiente&page=1&limit=10
Respuesta exitosa: 200 OK (data + paginacion)

GET /api/solicitudes/enviadas
Descripción: Lista las solicitudes que el usuario autenticado envió.
Protegido: Sí
Encabezado:
Authorization: Bearer <token>
Parámetros opcionales: estado, page, limit
Respuesta exitosa: 200 OK (data + paginacion)

GET /api/solicitudes/:id
Descripción: Consulta una solicitud del usuario (emisor o receptor).
Protegido: Sí
Encabezado:
Authorization: Bearer <token>
Nota: si la solicitud no existe o el usuario no participa responde 404.
Respuesta exitosa: 200 OK

PATCH /api/solicitudes/:id/aceptar
Descripción: Acepta la solicitud y crea la conexión entre ambos usuarios.
Protegido: Sí
Encabezado:
Authorization: Bearer <token>
Nota: solo puede aceptarla el receptor (403 en caso contrario). La solicitud
debe estar pendiente (409). La respuesta incluye data.solicitud con estado
"aceptada" y data.conexion con estado "activa".
Respuesta exitosa: 200 OK

PATCH /api/solicitudes/:id/rechazar
Descripción: Rechaza la solicitud pendiente.
Protegido: Sí
Encabezado:
Authorization: Bearer <token>
Nota: solo puede rechazarla el receptor (403). Debe estar pendiente (409).
Respuesta exitosa: 200 OK

PATCH /api/solicitudes/:id/cancelar
Descripción: Cancela una solicitud pendiente enviada por el usuario.
Protegido: Sí
Encabezado:
Authorization: Bearer <token>
Nota: solo puede cancelarla el emisor (403). Debe estar pendiente (409).
Respuesta exitosa: 200 OK

=========================================================
7. CONEXIONES
=========================================================
Todas las rutas son privadas: solo los dos participantes de una conexión pueden
consultarla o finalizarla.
Valores permitidos:
  estado -> activa, finalizada, bloqueada
  page   -> entero entre 1 y 100000 (por defecto 1)
  limit  -> entero entre 1 y 50 (por defecto 10)

GET /api/conexiones
Descripción: Lista las conexiones en las que participa el usuario autenticado.
Protegido: Sí
Encabezado:
Authorization: Bearer <token>
Parámetros opcionales: estado, page, limit
Ejemplo: GET /api/conexiones?estado=activa&page=1&limit=10
Nota: cada conexión incluye los datos públicos de emisor y receptor, el campo
"interlocutor" con la otra persona vista desde el usuario autenticado y
"noLeidos" con los mensajes recibidos que aún no se leyeron.
Respuesta exitosa: 200 OK (data + paginacion)

GET /api/conexiones/:id
Descripción: Consulta una conexión en la que participa el usuario.
Protegido: Sí
Encabezado:
Authorization: Bearer <token>
Nota: si la conexión no existe o el usuario no participa responde 404.
Respuesta exitosa: 200 OK

PATCH /api/conexiones/:id/finalizar
Descripción: Finaliza una conexión activa.
Protegido: Sí
Encabezado:
Authorization: Bearer <token>
Nota: puede hacerlo cualquiera de los dos participantes (404 si no participa).
Si la conexión ya no está activa responde 409.
Respuesta exitosa: 200 OK

=========================================================
8. MENSAJERÍA
=========================================================
Todas las rutas son privadas: solo los dos participantes de una conexión pueden
leer y escribir sus mensajes. Cualquier otro usuario recibe 404.
Valores permitidos:
  conexionId -> entero positivo (filtro opcional del listado)
  contenido  -> texto de 1 a 1000 caracteres (se guarda recortado)
  page       -> entero entre 1 y 100000 (por defecto 1)
  limit      -> entero entre 1 y 50 (por defecto 10)

POST /api/mensajes
Descripción: Envía un mensaje a una conexión activa.
Protegido: Sí
Encabezado:
Authorization: Bearer <token>
Cuerpo:
{
  "idConexion": 7,
  "contenido": "Hola, ¿nos vemos el sábado para practicar?"
}
Nota: si la conexión no existe o el usuario no participa responde 404.
Si la conexión está finalizada o bloqueada responde 409.
Respuesta exitosa: 201 Created
Campos de cada mensaje: idMensaje, idConexion, remitente (idUsuario, nombres,
apellidos, alias), contenido, leido, fechaEnvio y esPropio.

GET /api/mensajes
Descripción: Lista los mensajes visibles para el usuario autenticado.
Protegido: Sí
Encabezado:
Authorization: Bearer <token>
Parámetros opcionales: conexionId, page, limit
Ejemplo: GET /api/mensajes?conexionId=7&page=1&limit=20
Nota: el orden es cronológico ascendente. Sin conexionId se listan los mensajes
de todas las conexiones del usuario. Si la conexión indicada no existe o no le
pertenece responde 404.
Respuesta exitosa: 200 OK (data + paginacion)

PATCH /api/mensajes/leidos
Descripción: Marca como leídos los mensajes recibidos en una conexión.
Protegido: Sí
Encabezado:
Authorization: Bearer <token>
Cuerpo:
{
  "idConexion": 7
}
Nota: solo afecta a los mensajes que el usuario recibió; los propios no se tocan.
Si la conexión no existe o el usuario no participa responde 404.
Respuesta exitosa: 200 OK (data: idConexion y actualizados)

GET /api/mensajes/no-leidos
Descripción: Resume los mensajes sin leer del usuario agrupados por conexión.
Protegido: Sí
Encabezado:
Authorization: Bearer <token>
Respuesta exitosa: 200 OK (data: total y porConexion)
Nota: las rutas de conexiones (sección 7) incluyen el campo "noLeidos" con la
misma información aplicada a cada conexión del listado.

=========================================================
9. CALIFICACIONES
=========================================================
Todas las rutas son privadas. Una calificación pertenece a una conexión
finalizada y va siempre del usuario autenticado a la otra persona de la conexión.
Valores permitidos:
  puntuacion -> entero entre 1 y 5
  comentario -> texto opcional de hasta 500 caracteres
  page       -> entero entre 1 y 100000 (por defecto 1)
  limit      -> entero entre 1 y 50 (por defecto 10)

POST /api/calificaciones
Descripción: Califica a la otra persona de un intercambio finalizado.
Protegido: Sí
Encabezado:
Authorization: Bearer <token>
Cuerpo:
{
  "idConexion": 7,
  "puntuacion": 5,
  "comentario": "Explicó con paciencia y llegó puntual."
}
Nota: el calificado se deduce de la conexión y no se recibe del cliente.
Si la conexión no existe o el usuario no participa responde 404.
Si la conexión no está finalizada o ya fue calificada responde 409.
Respuesta exitosa: 201 Created
Campos: idCalificacion, idConexion, calificador (idUsuario, nombres, apellidos,
alias), calificado (idUsuario, nombres, apellidos, alias), puntuacion,
comentario, fechaCalificacion y esPropia.

GET /api/calificaciones/usuario/:id
Descripción: Lista las calificaciones recibidas por un usuario.
Protegido: Sí
Encabezado:
Authorization: Bearer <token>
Parámetros opcionales: page, limit
Ejemplo: GET /api/calificaciones/usuario/8?page=1&limit=10
Nota: si el usuario no existe responde 404.
Respuesta exitosa: 200 OK (data + resumen + paginacion)
El objeto resumen contiene total, promedio (dos decimales) y distribucion
(cantidad de calificaciones por cada puntuación de 1 a 5).

GET /api/calificaciones/conexion/:id
Descripción: Lista las calificaciones de una conexión.
Protegido: Sí
Encabezado:
Authorization: Bearer <token>
Nota: si la conexión no existe o el usuario no participa responde 404.
Devuelve como máximo dos calificaciones (una por participante).
Respuesta exitosa: 200 OK (data + puedeCalificar)
"puedeCalificar" es true cuando la conexión está finalizada y el usuario
autenticado todavía no calificó el intercambio.

Nota: el promedio también aparece como "calificacion" ({ promedio, total }) en
GET /api/usuarios/:id y GET /api/usuarios/perfil.
